# 2026-08-02 반복 오류 복구

## 증상

- 글 생성이 Qwen 429 이후 장시간 반복 재시도하다 `error`로 누적됨.
- 터미널의 새 Gemini 키와 장기 실행 서비스가 읽는 키가 달라 폴백이 동작하지 않음.
- 네이버 글쓰기 링크 클릭 타임아웃, 카테고리 누락, URL 미변경에도 발행 성공으로 기록될 수 있었음.
- 프로세스 재시작 후 `researching`, `writing`, `publishing` 상태가 고착됨.

## 변경

- `.env` 변경 감지, 429/인증/클라이언트 오류 분류, 제공자별 회로 차단과 즉시 폴백 추가.
- 게시물에 `retry_count`, `retry_after`, `last_error`를 추가하고 지수 백오프 적용.
- 시작 시 중간 상태 자동 복구, 스케줄러의 재시도 시각 필터 추가.
- 품질 기준을 통과한 글의 전체 재편집을 생략해 큰 출력 호출을 절감.
- 초안 직후 조기 발행 경쟁 상태를 없애고 품질·SEO 완료 후에만 예약 상태로 전환.
- 네이버 글쓰기 DOM 클릭, 고유 임시파일, 필수 카테고리 선택, URL/RSS 발행 검증 적용.
- 발행 확인 실패 시 `scheduled`로 복귀하고 재시도 전 RSS 중복 확인.
- 세션 만료 시 계정 단위로 발행을 멈추고 재로그인 성공 시 자동 재활성화.
- 통계 수집 실패 때 생성하던 임의 방문자 수 제거.
- 과거 밀린 38건을 보존 취소하고 현재·향후 20건만 순차 재처리.

## 검증

- 전체 Python 파일 AST 파싱 통과.
- 회로 차단·즉시 Gemini 폴백·재시도 시각·발행 상태 전이 단위 테스트 5개 통과.
- 실제 최소 호출에서 Qwen 429 후 Gemini 응답 성공 확인.
- LaunchAgent 실행 및 대시보드 HTTP 200 확인.

## 남은 위험

- Qwen Token Plan 자체 한도는 2026-08-05 리셋 전까지 복구되지 않음.
- 네이버 UI 변경과 로그인 만료는 외부 상태이므로 재시도 후 세션 갱신이 필요할 수 있음.
